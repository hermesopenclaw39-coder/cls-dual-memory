# CLS 双记忆系统：LoRA 作为记忆槽

[English](README.md) | **简体中文**

> 语言模型能不能把事实记忆存在**权重**里，而不是上下文里？这个仓库是一串围绕这个问题的实验：每条事实一个 rank-8 LoRA、余弦门控、回放巩固——以及把它们认真测一遍之后得到的基线和反例。
>
> Qwen2.5-7B-Instruct，4-bit QLoRA，合成事实，单张 RTX 5090 / 4090。

---

## 当前结论（2026-10-23）

五条，按我自己的信心排序。细节和原始日志见下文各节与 [`docs/report.md`](docs/report.md)。

1. **per-fact LoRA 确实能回答训练时没见过的问法。** 50 个独立适配器，每个在一条句子上训 100 步，然后用改写过的问句提问：**46/50（92%）**。我之前报的 16% 是脚本 bug——训练循环里没有在每条事实前重置 LoRA 权重，所以第 j 个「适配器」其实是在前 j 条事实上一路训过来的。修好重跑，92%。
2. **但 50 条这个规模上，ICL 已经是 100%。** 24 token 预算下，把 50 条全塞进 prompt 就是 50/50。这个规模上，这套架构还没赢过它本来想替代的基线。
3. **冻结语言模型的池化隐状态是个差检索器。** 末层均值在 400 条时 top-1 是 59%，800 条 53%；同一任务 BM25 是 100%，33M 参数的 bge-small 是 97–99%。改用 late interaction（ColBERT 式 MaxSim）能把 7B 的隐状态救到 80%/74%。
4. **「检索 + 上下文阅读」确实有效——但它是 RAG，不是权重记忆。** MaxSim 取 top-5 → 只把这五条原文放进 prompt → 回答：400 条 94%、800 条 83%，对应全上下文 ICL 的 93%/85%，而 prompt 只用 **约 110 token 而不是 7,865–15,807**。这条管线里**没有任何适配器**，之前那句「记忆存在权重里」是错的，撤回。
5. **还没回答的问题。** per-fact LoRA 在 400 条以上还成不成立（400 个适配器 × 100 步约 1.6 小时，还没跑）；以及每个适配器用多种表述训练、测没见过的表述是否有帮助。后者第一次试是 29/50（58%），但**不干净**：每种表述只给了 40 步，测试问句集也和上表不同。

## 这个仓库真正新增的东西

- **路由的失败是可测量、可修的**：把一句话压成一个向量会抹掉实体名；late interaction 保住了它。
- **补全不等于回答**，而一个忘记重置适配器的训练循环，会把「互相独立的记忆」悄悄变成「顺序学习」（本仓库真的写错过一次，`49fb249` 存着那版）。
- **同一批事实上的检索器排序**：BM25 100% > bge-small 97–99% > 7B MaxSim 74–80% > 7B 均值 11–59%。

## 1. 原始实验

| 阶段 | 召回（50 条） |
|---|---|
| 冻结底座 | 0/50 |
| 海马体：50 × rank-8 LoRA + 余弦门控 | 44/50 |
| 共享 LoRA 顺序学习 | 1/50 |
| 单适配器巩固（rank-32） | 0/50 |
| 分组巩固（9 × rank-8） | 50/50（oracle 分组） |

注意 44/50 用的是**前缀提问**——问题就是被记住那句话的开头，模型接着往下写。第 6 节用真正的问句重做了这件事。

## 2. ICL 基线

50 条全部进 system prompt：12 token 预算下 **44/50**，24 token 下 **50/50**。12 token 那 6 条全是截断，不是答错。零训练，22 秒。

## 3. 规模扫描

| 事实数 | ICL 召回 | prompt token | 路由（均值） | 路由（MaxSim） |
|---|---|---|---|---|
| 50 | 100% | 954 | 88.0% | — |
| 100 | 98% | 1,890 | 82.0% | — |
| 200 | 93% | 3,880 | 66.0% | — |
| 400 | 97% | 7,865 | 59.2% | 100% |
| 800 | 79% | 15,807 | 53.2% | 100% |

前缀式提问。1,600 条时 prompt 33,466 token，已经超出 32k 窗口。

> **故意留着的测量陷阱。** 这轮扫描的第一版用统一句式，门控在 N=50 只有 48%；同样的代码换回手写事实是 94%——句子太像，任何 embedding 都分不开。同质的合成事实测出来的是模板，不是方法。旧结果留在 `results/icl_scaling.csv` 里当反面样本。

## 4. 换成真问句

六种问句模板，每种事实类型一个（`What passcode does the X protocol use?`）：

| 事实数 | ICL | 检索 + 上下文阅读 | MaxSim 路由 | 均值路由 |
|---|---|---|---|---|
| 400 | 93%（7,865 token） | **94%**（约 110 token） | 80.5% | 13.5% |
| 800 | 85%（15,807 token） | 83%（约 110 token） | 74.0% | 10.7% |

![修好门控之后](results/fig_routing_fix.png)

「检索 + 上下文阅读」那一列是 RAG：它检索的是事实**原文**，再放进 prompt。这是本仓库里性价比最高的一条管线，而它一个适配器都没用。

## 5. 同一任务上的检索器

| 检索器 | 400 | 800 | 单次耗时 |
|---|---|---|---|
| BM25 | 100% | 100% | 0.1 ms |
| bge-small-en-v1.5（33M） | 98.8% | 97.4% | 0.5 ms |
| Qwen 7B late interaction | 80.5% | 74.0% | 2 ms |
| Qwen 7B 均值 | 13.5% | 10.7% | 2 ms |

前提：每个问句都带着实体名，这正是 BM25 能吃到的信息。

## 6. per-fact LoRA：补全 vs 问答

50 个适配器，每个在一条句子上训 100 步，**每条事实训练前重置权重**：

| 提问 | 召回 |
|---|---|
| 训练时没见过的改写问句 | **46/50（92%）** |
| 同上，但用 BM25 路由代替 oracle | 46/50 |

仓库里早先那个 16%、「只会补全」的结论来自 bug：适配器从不重置，第 j 个已经学过前 j 条。那是带快照的顺序学习，不是独立记忆。修好之后，适配器能回答真问题。

**多表述实验**（陈述句 + 两种问法训练，测第三种）是 29/50（oracle）、25/50（路由）。这**不是**一次干净的检验：每种表述只训了 40 步而不是 100 步，留出的问句集也和上表不同。只能当预实验看。

## 7. 还没有建立的

- **规模**：per-fact LoRA 只在 50 条上测过。400 个适配器约 1.6 小时训练，这是目前最值得补的一个数。
- **胜出条件**：在所有测过的规模上，ICL 的准确率都不低于它。这套架构现在能主张的是**成本**（110 vs 15,807 prompt token），不是准确率。
- **真实问句**：这里的问句都是模板。真正改写、甚至不出现实体名的问句，会同时打击 BM25 和 MaxSim。
- **单种子、单模型**：所有数字都是 Qwen2.5-7B-Instruct 上的一次运行。

## 复现

| 脚本 | 测什么 |
|---|---|
| `src/cls_demo_7b_50.py` | 原始五阶段流程 |
| `src/baseline_icl.py` | 固定条数下的 ICL 基线 |
| `src/baseline_scale.py` | ICL 随条数变化 |

```bash
pip install -r requirements.txt
python src/baseline_icl.py          # 需要 7B 权重
python src/retrieval_baselines.py   # BM25 部分不需要 LLM
```

`src/facts_scaled.py` 负责生成事实集（统一 / 多样 / 多问法），全部固定种子、可复现。原始日志在 `results/logs/`。
